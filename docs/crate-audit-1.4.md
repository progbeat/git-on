# Dependency reuse audit for milestone 1.4.0

Audited master: `27cd1e5c336541566f9497186425c44e4aa46f73`.
Decisions precede the resource-path changes; this document records the code/API
inspection rather than a general dependency-upgrade campaign.

| Function | Decision | Code, API and tradeoff |
| --- | --- | --- |
| CLI | Retain clap Builder and boundary parser | `src/cli.rs` already shares clap help/schema. The first `--`, literal child argv and byte-exact option-looking/non-UTF8 operands require the current boundary handling. Derive adds no needed behavior. Existing CLI/native Git oracle tests remain the gate. |
| Memory cache | Adopt lru 0.16.3, default features off | Expected O(1) original-OID lookup, promotion and eviction. Retain at most one entry per object: whole small content or one large-file block, shared across FDs. Account payload Vec capacity plus conservative node/table overhead against 16 MiB, without a separate object-count cap. Geometric table shrink charges rebuild work to actual evictions. Active readers hold object identities instead of payload Arc copies. Metadata retention is separate and measured. MSRV 1.70, MIT. |
| Temporary progress | Adopt indicatif 0.18.3, default features off | One ASCII spinner, delayed 500 ms, stderr TTY only, disabled for TERM=dumb. RAII clears and joins before child launch/error return. console, portable-atomic and unit-prefix are its native dependencies; no renderer, Unicode-width or async runtime is required. MSRV 1.71, MIT. |
| Ratatui | Reject for this scope | Inline rendering exists, but no application UI, layout, input handling or full-screen state is required. |
| Global persistent cache | Remove | The confirmed scope keeps only private per-invocation Git object storage. Removing cross-run persistence removes its file index, flock, serialization, fsync, retention and crash-recovery code altogether. Historical directories are untouched; no replacement daemon is introduced. |
| rusqlite | Reject for this scope | There is no persistent cache to index. A database would introduce unnecessary native build/schema and maintenance cost. |
| Moka / memory LRU for disk | Reject for this scope | Cross-run disk persistence is removed; retain the existing bounded decoded memory cache instead. |
| Git object decoding | Retain git2 0.20.4 / vendored libgit2 1.9.7 and native Git | Odb::reader streams local loose decoded bytes (compressed source is mmap-backed); the pack backend lacks readstream and may require whole-object/delta decoding. Native Git cat-file streams just-received remote objects into raw run storage. This avoids blob recompression, duplicate loose writes and cumulative pack discovery; its big-file threshold streams large non-delta blobs. Required delta decoding remains. |
| Hash verification | Adopt RustCrypto sha1-checked 0.10.0 | Computes the canonical Git type/size/payload digest incrementally before publishing staged data, rejecting collision detections as described below. It shares the digest dependency closure with sha2 and uses sha1 internally. MIT OR Apache-2.0, verified by the Rust 1.89 locked-graph gate. SHA-1 identifies Git's existing object format; this does not add SHA-256 repository support. |
| Pack descriptors | Retain libgit2 resource policy | opts::set_mwindow_file_limit already supplies LRU closure of inactive pack windows. Set once before threads, capped at 32 and a quarter of effective RLIMIT_NOFILE; do not raise the OS limit. Temporary Repository/ODB/object handles remain scoped to operations. |
| Temporary files / signals | Retain tempfile and signal-hook | Each raw object has one OID-named file beneath an owned anchored directory; operation-scoped file descriptors avoid one retained FD per object. Atomic preparation and anchored no-follow operations preserve failure cleanup and resist path substitution. Transient protocol/decoder files retain bounded parts and inherited FSIZE handling. Existing scoped native-output and signal ownership remain. |
| Run-local raw-blob lookup | Reuse std HashMap and tempfile | The author selected a simple trusted RAM map for original OID, type, length and packed block hashes. Expected amortized O(1) lookup/promotion; payload hashing and real evictions are charged explicitly. Metadata grows with touched unique objects rather than all repository contents. No disk index, database or daemon is needed. |
| Prepared-disk integrity | Reuse RustCrypto sha2; remove hmac/subtle | Full canonical collision-detecting Git SHA-1 verifies the same decoded stream from which ordered SHA-256 block digests are formed. Publish trusted RAM descriptors only after success. On reload, verify requested 64 KiB blocks against those protected expectations and copy from the checked buffer. Disk metadata cannot supply identity, order, size or expected hashes. HMAC and a secret are unnecessary when the expectations stay in trusted RAM; this follows the approved threat model excluding process-memory access. |
| Prepared directory names | Reuse std HashMap and Arc | Stream-parse each demanded unique tree once and publish the result only after canonical OID verification. Share immutable names between stable iteration order and direct lookup; retain parsed structures, including absence information, in protected RAM. Raw tree storage and authenticated disk name tables are removed. Separate per-path inode/parent state remains in the filesystem. Metadata growth and full enumeration costs are reported rather than hidden under the payload LRU. |
| Single-object pack inflation | Adopt flate2 1.1.10 with its zlib backend | Reuses already bundled libz-sys and adds crc32fast 1.5.3. Incremental Decompress state explicitly requires StreamEnd, exact compressed extent and canonical Git OID before raw publication. This avoids implementing DEFLATE or allocating a full decoded blob. Pack framing/checksum is bounded; complex/delta packs retain existing Git/libgit2 handling. The locked Rust 1.89, license and native-platform gates validate adoption. |
| Collision detection for direct imports | Adopt RustCrypto sha1-checked 0.10.0 | A direct received-pack decoder must preserve native Git's SHA1 collision-detection defense. Explicit try_finalize collision results are rejected for pack checksums and canonical object hashes. MSRV 1.72, MIT OR Apache-2.0; reuses the existing digest/sha1 dependency closure with collision-detection state and no native backend replacement. The public SHA-mbles vector is a permanent regression. SHA-1 remains Git's existing object format, not a promise of modern collision resistance. |
| Demand transport reuse | Reuse native Git diagnostics, upload-pack, SSH wrapper and HTTP helper | Git still resolves the original source/refspec. Optional --diag-url parsing preserves native decoded path/port bytes and falls back on unknown formats. Protocol v2 requests reuse one owned child; native HTTP helper retains credentials/proxy/TLS. Capability absence, custom server/vcs/fsck settings and GIT_EXEC_PATH retain native fetch. No second repository-URL parser, HTTP/TLS stack or daemon is introduced. The small bounded pkt-line adapter adds no protocol crate dependency; cryptography and inflation remain mature libraries. Cancellation, group ownership, old-protocol fallback and all-process costs require independent review and actual integrations. |
| clap_complete | Defer | Completion is optional new UX outside this milestone. |

API/maintenance evidence is the pinned crate source and Cargo manifests in the
locked graph, including libgit2's `odb_loose.c`, `odb_pack.c` and `mwindow.c`.
The dependency lock and target-specific notices identify the distributed closure.
MSRV, platform builds, license generation and observable behavior are validated
by the repository's existing Rust, macOS and native packaging checks. Measurements
and red/green regressions belong to the resource acceptance evidence, separately
from these adoption decisions.
