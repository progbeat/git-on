# 2.0.0
<!-- Bump: major -->

Breaking change: signals sent only to a command blocked in remote FUSE I/O no longer synthesize EINTR. The signal handler may wait for the current I/O to finish, with no runner-imposed deadline. To cancel the whole invocation, signal Git-on itself or the foreground process group. Whole-invocation cancellation stops owned operations and performs normal cleanup. Native FUSE_INTERRUPT support remains deferred until the backend supports it.

- Handle transport-helper exit before its first reply without hanging. Preserve prepared source data across descriptor exhaustion during copy-up. Transferred source files keep authenticating untouched bytes after partial writes, truncation and reopen, including concurrent temporary-file tampering, without a second decoded backing or repeated decoding.
- Stream loose Git objects into verified large source spools without an avoidable full decoded RAM buffer. Local packed objects still use libgit2's required object/delta decoding.
- Reuse verified contents after close/reopen and eviction within one invocation. A 16 MiB byte-accounted LRU retains at most one entry per original object: the complete small object or one block of a large object. New blocks replace that object's previous entry without invalidating active read buffers. Small resident data spills lazily; large objects stream to one raw file per original object. Readers retain descriptors, not payload allocations or open object files. Cache unchanged readonly source data in Linux, including all-policy source until copy-up, while preserving mutable-file coherence.
- Return authenticated read bytes when an optional cache spill fails, preserving the resident object in RAM within the existing budget. Required object preparation and invalid source or temporary-storage contents still fail.
- Handle inherited file-size write limits as ordinary errors and clean up temporary storage, mounts and pins. Preserve the caller's file-limit signal disposition in executed commands.
- Verify local and remote eager materialization directly into its destination, avoiding a duplicate full decoded copy on disk. Large remote blobs stream through the OID verifier from compressed Git storage. Repeated OIDs reuse prepared bytes across directories and file/symlink entries with integrity checks; writable file copies remain independent.
- Keep FUSE source data lazy across chmod, timestamp changes, links, renames and writable opens. Empty writes and unchanged-size truncation preserve source contents. Content mutations preserve independent files sharing an OID, including unopened paths and open-unlinked readers. The last original inode adopts its authenticated raw backing without copying; no second complete immutable copy is retained for a writable inode. Needed original bytes survive without refetch or repeat decoding. Truncation and later extension expose zeros rather than restoring removed source bytes. Ownership accounting reads tree metadata on the first destructive source operation, with remote trees batched by depth.
- Preserve the command's actual exit status after forwarding a signal and cleaning up, including a command that handles SIGTERM and exits normally while a remote read is active. Runner-initiated cancellation is separate from persistent transport, storage and integrity failures.
- Fetch eager demands individually under finite inherited file-size limits so batching does not combine small objects into an oversized pack. Unrestricted runs retain batching. Stream request input without a full temporary stdin file or an additional input thread.
- Keep original object identity, lengths and packed ordered SHA-256 block hashes in trusted RAM after complete Git OID verification. Disk reloads verify the exact buffer used for reads; unprivileged disk changes cannot replace these expectations. Temporary transport framing uses bounded parts to respect inherited file-size limits. Lazy FUSE remains demand-only; eager preparation batches already-required IDs.
- Parse touched Git directories once into shared immutable RAM structures with direct name lookup. Release raw tree bytes and remove disk directory indexes. Parsed metadata grows with touched objects outside the payload LRU; this is not a fixed total-RAM claim. Eager materialization reuses enumerated child metadata and checks host names without sorting every directory.
- Reuse owned packed-blob buffers already verified by the audited vendored libgit2 SHA1DC path, avoiding a second canonical hash and intermediate copy. Startup explicitly keeps strict native verification enabled; streams and unaudited/embedding paths retain independent verification. Temporary-storage range authentication remains unchanged.
- Reuse prepared directory views on reopen and read only the requested directory page. Keep per-stream cookies and names stable across namespace changes without allocating inode metadata or lifetime references for unread siblings. Immutable source paths retain stable inode identities when their cached metadata is evicted.
- Update merged directory views by name after namespace edits, sharing unchanged rows across active versions instead of repeatedly enumerating the source. Active streams keep their earlier names and cookies. Reuse one shared last-read raw descriptor, revalidating metadata and authenticating each disk-read buffer; release that slot before opening another object under tight descriptor limits.
- Cache policy-protected directory attributes in Linux as well as regular-source attributes. Generated directory membership stays live; mutable/generated and all-policy attributes retain zero TTL.
- Reuse Linux directory pages for the wholly readonly `none` policy on FUSE ABI 7.28+. Partial streams, seek cookies and reopen preserve the immutable namespace; mutable policies keep ordinary directory I/O.
- Avoid durability syncs for disposable remote object storage; caller repositories and signature/hash verification retain their existing contracts.
- Bound retained pack descriptors using the effective process descriptor limit, leaving room for active files and native Git startup. This fixes cold remote loading that could fail with “Too many open files”; git-on never raises your OS limits.
- Stream native decoder output directly through OID verification into private raw storage, without a complete decoded output file or a second loose blob copy. Keep native verification metadata in the run Repository. Available objects avoid repeated ODB refreshes, and later demands no longer scan all earlier per-object packs. Native Git streams large non-delta imports; necessary delta decoding remains. Linux native-operation waits wake on child exit without a fixed polling delay.
- Reuse invocation-owned protocol v2 channels for exact remote demands where supported, keeping native Git source/refspec resolution and HTTP credentials/proxy/TLS configuration. Stream verified single-object packs into raw storage without a new fetch/decoder client for every file. Callers with a controlling terminal, older protocols and custom fetch/server/fsck policy retain native fetch with foreground and job-control supervision; complex packs are imported without a second network fetch. Only requested blobs become decoded raw files; unrequested delta bases remain compressed and can satisfy a later explicit demand locally. No unrelated objects are prefetched.
- Remove the global persistent object cache and its disk maintenance. Remote objects stay in the private temporary repository for the invocation and are reused within that run; separate invocations fetch their own demanded objects again. Decoded memory caches remain bounded.
- Successful explicit-all materialization is quiet when output is redirected. Lengthy terminal preparation shows a temporary spinner that clears before the command starts, including error and interruption cleanup.
- Terminal progress pauses while native Git owns the foreground, including shells using `stty tostop`. Clean unmount waits for active inode reclamation, including when the launcher blocks SIGCHLD; a new cancellation during cleanup stops and reaps the owned helper group. Failed unmounts release the run lock and identify preserved recovery state for checked cleanup.
- Historical `git-on/objects-v1` and `objects-v2` cache directories under XDG_CACHE_HOME or HOME/.cache are left untouched. Git-on no longer requires those environment variables for object caching and starts no cache daemon.
- CLI argument bytes, write policies, object verification and demand-driven FUSE loading retain their existing contracts. macOS continues to support explicit-all materialization; native macOS mounts remain deferred. Repository and file counts have no artificial ceiling. WebKit at a recorded revision is the practical scale reference; synthetic regressions remain where they check a distinct behavior.
