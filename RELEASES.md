- Reuse available attributes in adaptive local Linux directory replies. Keep names-only listings from loading cold file headers, batch metadata only for requested later pages, and preserve directory cookies, inode lifetimes and mutable attributes.
- Let ready local protected-source reads progress while unrelated generated-file I/O waits on the native Linux backend. Keep request buffers and descriptors alive through asynchronous completion and drain owned work before unmount.
- Keep local loading and caches asynchronous when io_uring is unavailable. Use one lazy bounded file worker for disk operations; fitting source reads stay on the event loop without a worker job.
- Use the same native asynchronous source cache for local `all` operations and copy-up. Preserve renamed directory origins and order mutation after outstanding source READ replies.
- Reuse positive name lookups in native Linux `all` mounts while keeping mutable attributes live. Order namespace changes after outstanding LOOKUP replies and preserve cached-name coherence across replacement, links and directory moves.
- Reuse unchanged source and directory attributes in local Linux `all` mounts. Keep metadata ownership through LOOKUP/GETATTR replies, refresh modified regular files, and preserve parent attributes across namespace edits. Readonly source opens avoid an exclusive mutation gate and omit the no-op close flush; explicit sync retains its normal behavior.
- Close unchanged source descriptions without waiting for another description's source READ reply. Keep copy-up ordered after that reply and exclude closed descriptions when installing private backing handles.
- Keep remote FUSE metadata and verified payloads on the event loop too. Isolate native Git/transport waits on one bounded source thread, move verified allocations into the invocation cache, and preserve request cancellation, integrity failures, transport reuse and cleanup state. Reuse required delta-pack objects without an additional retained payload cache.
- Await source shutdown when FUSE startup fails, including mount errors before INIT, and retain cleanup failures in the startup diagnostic.
- Stream loose Git objects into verified large source spools without an avoidable full decoded RAM buffer. Local packed objects still use libgit2's required object/delta decoding.
- Reuse verified contents after close/reopen and eviction within one invocation. A 16 MiB byte-accounted LRU retains at most one entry per original object: the complete small object or one block of a large object. New blocks replace that object's previous entry without invalidating active read buffers. Small resident data spills lazily; large objects stream to one raw file per original object. Readers retain descriptors, not payload allocations or open object files. Cache unchanged readonly source data in Linux, including all-policy source until copy-up, while preserving mutable-file coherence.
- Keep original object identity, lengths and packed ordered SHA-256 block hashes in trusted RAM after complete Git OID verification. Disk reloads verify the exact buffer used for reads; unprivileged disk changes cannot replace these expectations. Temporary transport framing uses bounded parts to respect inherited file-size limits. Lazy FUSE remains demand-only; eager preparation batches already-required IDs.
- Keep full source paths only for directories; readonly file and symlink callbacks use their inode/OID without retaining ordered or reverse pathname indexes. Mutable policies retain the indexes required for copy-up and namespace changes.
- Parse touched Git directories once into shared immutable RAM structures with direct name lookup. Release raw tree bytes and remove disk directory indexes. Parsed metadata grows with touched objects outside the payload LRU; this is not a fixed total-RAM claim. Eager materialization reuses enumerated child metadata and checks host names without sorting every directory.
- Reuse owned packed-blob buffers already verified by the audited vendored libgit2 SHA1DC path, avoiding a second canonical hash and intermediate copy. Startup explicitly keeps strict native verification enabled; streams and unaudited/embedding paths retain independent verification. Temporary-storage range authentication remains unchanged.
- Reuse prepared directory views on reopen and read only the requested directory page. Keep per-stream cookies and names stable across namespace changes without allocating inode metadata or lifetime references for unread siblings. Immutable source paths retain stable inode identities when their cached metadata is evicted.
- Update merged directory views by name after namespace edits, sharing unchanged rows across active versions instead of repeatedly enumerating the source. Active streams keep their earlier names and cookies. Reuse one shared last-read raw descriptor, revalidating metadata and authenticating each disk-read buffer; release that slot before opening another object under tight descriptor limits.
- Remove per-operation requester signal polling. Wait for temporarily delayed sources without synthesizing read errors or EINTR. Whole-invocation cancellation and child-exit cleanup remain; signals sent only to a command blocked in FUSE may wait for its current I/O to complete. Native FUSE_INTERRUPT support remains deferred until the backend supports it.
- Cache policy-protected directory attributes in Linux as well as regular-source attributes. Generated directory membership stays live; modified/generated regular-file attributes retain zero TTL; local `all` directory attributes use coherent cached replies.
- Reuse Linux directory pages for the wholly readonly `none` policy on FUSE ABI 7.28+. Partial streams, seek cookies and reopen preserve the immutable namespace; mutable policies keep ordinary directory I/O.
- Avoid durability syncs for disposable remote object storage; caller repositories and signature/hash verification retain their existing contracts.
- Bound retained pack descriptors using the effective process descriptor limit, leaving room for active files and native Git startup. This fixes cold remote loading that could fail with “Too many open files”; git-on never raises your OS limits.
- Decode received remote blobs directly into private raw storage instead of recompressing and writing loose blob copies. Keep native verification metadata in the run Repository. Available objects avoid repeated ODB refreshes, and later demands no longer scan all earlier per-object packs. Native Git streams large non-delta imports; necessary delta decoding remains. Linux native-operation waits wake on child exit without a fixed polling delay.
- Reuse invocation-owned protocol v2 channels for exact remote demands where supported, keeping native Git source/refspec resolution and HTTP credentials/proxy/TLS configuration. Stream verified single-object packs into raw storage without a new fetch/decoder client for every file. Older protocols and custom fetch/server/fsck policy retain the native compatibility path; complex packs are imported without a second network fetch. No unrelated objects are prefetched.
- Remove the global persistent object cache and its disk maintenance. Remote objects stay in the private temporary repository for the invocation and are reused within that run; separate invocations fetch their own demanded objects again. Decoded memory caches remain bounded.
- Successful explicit-all materialization is quiet when output is redirected. Lengthy terminal preparation shows a temporary spinner that clears before the command starts, including error and interruption cleanup.
- Terminal progress pauses while native Git owns the foreground, including shells using `stty tostop`. Clean unmount waits for active inode reclamation rather than failing large successful traversals after three seconds; completed busy-mount failures still preserve recovery state.
- Historical `git-on/objects-v1` and `objects-v2` cache directories under XDG_CACHE_HOME or HOME/.cache are left untouched. Git-on no longer requires those environment variables for object caching and starts no cache daemon.
- CLI argument bytes, write policies, object verification and lazy FUSE behavior remain unchanged. macOS continues to support explicit-all materialization; native macOS mounts remain deferred. Repository and file counts have no artificial ceiling. WebKit at a recorded revision is the practical scale reference; synthetic regressions remain where they check a distinct behavior.
